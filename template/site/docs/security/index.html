Security model

Example Seed stores project names and owners, not secrets, but it still treats every request as untrusted. This page describes what the registry protects, how and where the boundaries are.

Authentication

Every request carries an API key as a bearer token. The registry stores only a hash of each key, compares hashes in constant time and rejects a request without a valid key before it reads anything.

Authorization

A key belongs to one account and has scopes. A key with the projects scope can create and read that account's projects and nothing else; there is no way for a key to read another account's records.

Transport and storage

The hosted registry accepts HTTPS only. Records are stored in PostgreSQL with encryption at rest, and the registry connects to the database over TLS.

Reporting a vulnerability

Email security reports to the address in the repository's security policy. Reports are acknowledged within two working days, and fixes are noted in the changelog once they ship.
