How Example Seed works

Example Seed is a project registry with an HTTP API. A team names each project once, and every tool that needs to know about that project reads the same record from the registry instead of keeping its own copy. This page covers the ideas the rest of the guide builds on.

Concepts

Project

A project is the unit Example Seed keeps track of. It has a name, a creation time and an owner. You create it with one request and read it back by name from any service, script or pipeline.

Name

A name is lowercase letters, digits and hyphens. Names are unique within an account and never reused, so a link that contains a name keeps pointing at the same project.

Registry

The registry is the service that stores projects and answers reads. You can use the hosted registry or run the open-source registry on your own servers; both expose the same API.

The flow

A request comes in over HTTPS with an API key. The registry checks the key, validates the name, writes the project to its store and returns the stored record. Reads go straight to the store and return the same record shape, so clients need one parser for both.
