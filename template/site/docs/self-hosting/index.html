Self-hosting and operations

The registry is open source and runs anywhere you can run a container and a PostgreSQL database. The self-hosted registry has the same API as the hosted one, so clients only change their base URL.

Requirements

You need a container runtime, PostgreSQL 15 or newer and a TLS-terminating proxy or load balancer in front of the service. The registry itself uses little memory and no local disk.

Install

Run the registry image with DATABASE_URL set to your database. On first start it creates its table and index, then listens on PORT. Point your load balancer at it and set SEED_BASE_URL in your clients to the new address.

Upgrades

Each release notes any database change in the changelog. The registry applies changes at startup, and releases keep reading the previous schema, so a rolling upgrade works without downtime.

Backups and monitoring

All state is in PostgreSQL, so your normal database backups cover the registry. The service exposes a health endpoint for your load balancer and logs one line per request for your log pipeline.
