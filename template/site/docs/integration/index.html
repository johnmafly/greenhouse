Integration guide

Most teams connect Example Seed to the places that already know about projects: their CI system, their deploy pipeline and their internal services. Each integration is a few HTTP calls.

CI pipelines

Read the project at the start of a pipeline so every job uses the registry's record instead of a hard-coded value. Store the API key in your CI system's secret store and pass it as a bearer token:

curl https://api.example.com/v1/projects/first-project \
  -H "authorization: Bearer $SEED_API_KEY"

Deploy pipelines

Create the project when a new service is set up, before its first deploy. The create call fails with a clear error when the name is taken, which stops a second service from claiming the same name.

Internal services

Services read projects through the SDK or plain HTTP. Cache a record for as long as your service runs; names never move to another project, so a cached record never points at the wrong one.

Webhooks and events

Example Seed answers requests and sends no events. Services that need to react to a new project read the registry on their own schedule.
