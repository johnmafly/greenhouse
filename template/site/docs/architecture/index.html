Architecture

Example Seed has three parts: clients that call the API, the registry service that validates and answers requests, and the store that keeps project records. Each part has one job, and the boundaries between them are plain HTTP and SQL.

Registry service

The registry is a stateless HTTP service. It authenticates each request with an API key, validates the project name against the naming rules and translates the request into one read or one write. Because it holds no state of its own, you can run as many copies as your traffic needs behind any load balancer.

Store

Project records live in a PostgreSQL database. Each record is one row keyed by account and name, with a unique index that enforces the naming rule at the database level as well as in the service.

Clients

Clients are anything that speaks HTTP: the SDK, the command line, CI jobs and your own services. They never touch the store directly, which keeps validation in one place.
